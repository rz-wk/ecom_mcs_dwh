# Сопровождение и диагностика

## Сопровождение

| Событие | Действие |
|---|---|
| Добавлен новый месяц CSV | Дополнительных действий не требуется: `emit_csv` регистрирует сущность и создаёт ребро |
| Добавлена новая dbt-модель | Дополнительных действий не требуется: `emit_dbt` читает manifest, обновляемый задачей `refresh_dbt_manifest` |
| На этапе ODS -> Core появилась новая таблица | Добавить соответствующие `inputs/outputs` в `emit_spark.py` |
| Добавлен новый дашборд Superset | Обновить фильтры агента: заголовок дашборда и идентификаторы его чартов; см. [setup.md](setup.md), шаг 5 |
| Добавлен новый этап конвейера | Создать эмиттер по шаблону [emitters/](emitters/README.md) и добавить задачу в DAG |
| После экспериментов с интеграциями остались лишние сущности | Использовать `Mark Deleted`, затем при необходимости выполнить hard-delete с `recursive=true` |
| Обнаружен незапланированный дубль таблицы | Проверить include-фильтр схемы соответствующего ingestion-сервиса |

## Типовые проблемы

| Симптом | Возможная причина | Решение |
|---|---|---|
| Ответ `no lineage edges created` с кодом `200` | Датасет отсутствует в OM или `namespace` не совпадает с именем сервиса | Проверить существование обеих сущностей и формат датасета в [architecture.md](architecture.md) |
| Ребро появилось не на той таблице | Есть дубликаты сущностей из-за отсутствия фильтров схем | Исправить include-фильтры; затем выполнить дедупликацию по инструкции в [setup.md](setup.md), шаг 1 |
| Ошибка `400 query param type must not be null` | Schema-facet от Cosmos listener не содержит типов полей | Для текущей конфигурации это известное ограничение; dbt-рёбра строит `emit_dbt`. Ошибку Cosmos не следует путать с результатом работы dbt-эмиттера |
| Superset-агент обнаружил 0 дашбордов | Фильтр дашбордов задан по идентификатору, а применяется к заголовку | Использовать паттерн по заголовку дашборда |
| Ошибка `chart instance not found` | Chart-фильтр исключает чарты, на которые ссылается включённый дашборд | Включить в паттерн все чарты выбранных дашбордов |
| Эмиттер отработал, но в логе нет строк `INFO` | В модуле не настроено логирование | Добавить вызов `configure_logging()`. `ol.py` и `emit_spark.py` импортируют его, но сами по себе не вызывают |
| Эмиттер ничего не делает без явной ошибки | Отсутствует защита точки входа `__main__` либо при запуске недоступен `requests` | Проверить `if __name__ == "__main__"` и наличие `requests` в используемом Python |
| Superset-агент не подключается | Контейнер OM не может обратиться к `localhost` хоста | Использовать `host.docker.internal:8088` |
| Статусы DAG не обновляются в OM | Транспорт задан переменной окружения вместо конфигурации провайдера | Проверить секцию `[openlineage]` в `airflow.cfg` и перезапустить процессы Airflow |

## Проверка здоровья после запуска DAG

Запросить lineage для витрины `mart_sales`:

```bash
OM=http://127.0.0.1:8585/api/v1
T="Authorization: Bearer <token>"

curl -s -H "$T" \
  "$OM/lineage/getLineage?fqn=clickhouse_marts.ecom_mcs_dwh_marts.ecom_mcs_dwh_marts.mart_sales&type=table&upstreamDepth=4&downstreamDepth=3" \
  | python3 -c "import sys,json;[print(n) for n in json.load(sys.stdin)['nodes']]"
```

Вместо `<token>` подставляется действующий токен OM.

### Критерий проверки

В списке ожидаются восемь узлов сквозного пути:

1. CSV-таблица;
2. `ods.events`;
3. `fact_events`;
4. `fact_purchases`;
5. `dim_category`;
6. `mart_sales`;
7. `superset.model.<id>` — датасет Superset;
8. `superset.<id>` — дашборд.

Если отсутствует верхняя часть цепочки, проверить `emit_csv`: зарегистрирована ли CSV-сущность и создано ли ребро.

Если отсутствует средняя часть, проверить `emit_spark` и `emit_dbt`, а также существование сущностей и соответствие FQN.

Если отсутствует нижняя часть, проверить настройки и результаты Superset ingestion-агента.
