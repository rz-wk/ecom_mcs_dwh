# `ol.py` — общий helper

Файл: `src/lineage/ol.py`.

Используется всеми эмиттерами; отдельно в DAG не запускается.

## `emit(inputs, outputs)`

Отправляет OpenLineage `RunEvent` от имени пайплайна `ecom_mcs_dwh_daily_pipeline`. Событие создаёт рёбра между входными и выходными датасетами: каждый вход связывается с каждым выходом.

Особенности:

- Формат датасетов — имя сервиса OM и хвост FQN; см. [architecture.md](../architecture.md).
- Обе стороны каждого ребра должны существовать в OM. Если датасет отсутствует, endpoint может вернуть `200`, не создав рёбер.
- Каждый вызов получает новый `runId`, поэтому в OM сохраняется история событий.
- Ошибки отправки логируются и не пробрасываются вызывающему коду.

Настройки считываются из переменных окружения `OM_API`, `OM_LINEAGE_URL`, `OM_TOKEN`. Если переменные не заданы, используются значения конфигурации проекта `om.api`, `om.lineage_url`, `om.token`.

Токен должен соответствовать используемой конфигурации OM. Его нельзя публиковать в репозитории или документации.

## `register_csv_table(name, csv_path, columns)`

Регистрирует CSV-файл как таблицу `csv_staging.raw.staging.<имя>`.

Функция создаёт иерархию:

```text
database:       raw
schema:         staging
table:          <имя>
```

Таблица регистрируется с типом `External`; колонки типа `STRING` формируются по заголовку исходного файла.

Все операции выполняются через идемпотентные PUT-запросы: повторный вызов обновляет колонки и описание, не создавая дубликат сущности.

### Требования к имени

Имя таблицы — stem исходного файла без расширения и без точек.

Пример:

```text
data/raw/2020-04.csv
  -> csv_staging.raw.staging.2020-04
```

Точка используется как разделитель FQN. Если оставить имя `2020-04.csv`, оно будет интерпретировано как дополнительные уровни иерархии.

## Масштабирование: второй пайплайн

В текущей реализации `JOB` задан жёстко. Все события эмиттеров привязываются к `ecom_mcs_dwh_daily_pipeline`.

При добавлении второго DAG необходимо параметризовать `JOB` — например, передавать его аргументом эмиттера или использовать отдельную константу для каждого пайплайна. Иначе рёбра второго процесса могут оказаться привязаны к чужому пайплайну, а история запусков будет смешана.

`register_csv_table` можно использовать как образец для регистрации источников других типов. Иерархия база -> схема -> таблица создаётся последовательностью PUT-запросов к `/databases`, `/databaseSchemas` и `/tables`.

Для нового типа источника следует реализовать отдельную функцию по этому образцу в соответствующем эмиттере.
