# Эмиттеры

Эмиттер — скрипт, который регистрирует сущности или строит рёбра lineage в OpenMetadata для конкретного звена конвейера.

Все эмиттеры используют общий helper `ol.py`. Операции построения lineage выполняются в режиме best-effort: ошибки отправки логируются, но не прерывают основной DAG.

## Сводная таблица

| Звено | Скрипт | Таск DAG | Результат |
|---|---|---|---|
| CSV -> ODS | `src/lineage/emit_csv.py` | `emit_csv_lineage` | Сущность CSV-таблицы и ребро к `ods.events` |
| ODS -> Core | `src/lineage/emit_spark.py` | `emit_spark_lineage` | Ребро `ods.events` -> `fact_events` |
| dbt-граф | `src/lineage/emit_dbt.py` | `emit_dbt_lineage` | Рёбра между таблицами моделей и их зависимостями |
| Общая логика | `src/lineage/ol.py` | — | Отправка OpenLineage-событий и регистрация CSV-таблиц |

## Карточки эмиттеров

- [ol.md](ol.md) — общий helper: формат датасетов, отправка событий, регистрация CSV-сущностей.
- [csv.md](csv.md) — построение зависимости CSV -> ODS.
- [spark.md](spark.md) — ручная фиксация зависимости ODS -> Core.
- [dbt.md](dbt.md) — построение графа dbt из `manifest.json`.

## Масштабирование

| Что добавляем | Что требуется |
|---|---|
| Новый месяц CSV | Ничего: `emit_csv` создаёт сущность и ребро при запуске |
| Новая dbt-модель или source | Дополнительных правок эмиттера не требуется, если модель или source корректно отражены в manifest и соответствующие сущности существуют в OM |
| Новая таблица на этапе ODS -> Core | Обновить списки `inputs/outputs` в `emit_spark.py`; см. [spark.md](spark.md) |
| CSV-источник другого типа | Создать отдельную схему или сервис и эмиттер по шаблону `emit_csv.py`; см. [csv.md](csv.md) |
| Новый этап конвейера | Создать эмиттер по шаблону карточек и добавить соответствующий таск в DAG |
| Новая база dbt | Создать сервис OM с include-фильтром и добавить запись в `_DB_TO_SERVICE`; см. [dbt.md](dbt.md) |
| Второй DAG | Параметризовать `JOB` в `ol.py`, иначе события могут привязаться к чужому пайплайну |
| Новый дашборд Superset | Обновить фильтры агента; см. [../setup.md](../setup.md), шаг 5 |

### Добавление нового звена

1. Выбрать ближайший по назначению эмиттер и использовать его карточку как шаблон.
2. Добавить новую пару (сервис, база.схема.таблица) во входы и выходы эмиттера.
3. Убедиться, что все участвующие сущности существуют в OM.
4. Если для нового источника нет ingestion-коннектора, зарегистрировать сущность через REST PUT. Пример — функция `register_csv_table` в `ol.py`.
5. Добавить эмиттер в DAG после соответствующего этапа и проверить итоговый граф.
