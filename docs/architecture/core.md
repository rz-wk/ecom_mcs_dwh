# Core — ядро хранилища

## 1. Назначение

Core — центральный слой DWH на ClickHouse. Принимает результат обработки ODS в PySpark и служит источником для последующего моделирования данных в dbt. Cодержит очищенные события, производные фактовые таблицы, измерения.

Основные задачи слоя:
- хранение детализированных событий после обработки и контроля качества;
- предоставление согласованных данные для аналитических моделей;
- отделение подготовки данных от расчёта бизнес-показателей в витринах.

## 2. Архитектурный подход

В проекте используется гибридный подход Кимбалла: данные организованы вокруг фактов и измерений.

- Факты содержат события и рассчитанные на их основе показатели.
- Измерения описывают пользователей, товары и категории.
- Связь товара с категорией вынесена в отдельное измерение `dim_category`, что структурно приближает схему к Snowflake.
- Витрины формируются отдельно в dbt и адаптируют данные Core к конкретным аналитическим сценариям.

Таким образом, архитектура сочетает размерное моделирование Кимбалла с отдельным слоем аналитических витрин. Это позволяет повторно использовать базовые данные и не смешивать хранение событий с расчётом показателей для отчётности.

## 3. Состав схемы

Схема `ecom_mcs_dwh_core` включает:

| Таблица | Назначение |
|---|---|
| `fact_events` | Детализированные события пользователей |
| `fact_purchases` | Факты покупок |
| `fact_sessions` | Агрегированные показатели пользовательских сессий |
| `dim_user` | Временные границы активности пользователя |
| `dim_product` | Идентификаторы товаров и их категории, бренды |
| `dim_category` | Коды и иерархические атрибуты категорий |

### 3.1. Фактовые таблицы

#### `fact_events`

Основная таблица событий. Одна запись соответствует событию, прошедшему обработку и загрузку в Core.

| Поле | Тип ClickHouse | Описание |
|---|---|---|
| `event_id` | `UInt64` | Идентификатор события |
| `event_time` | `DateTime64(3, 'UTC')` | Время события |
| `event_type` | `LowCardinality(String)` | Тип события |
| `product_id` | `UInt32` | Идентификатор товара |
| `category_id` | `UInt64` | Идентификатор категории |
| `category_code` | `LowCardinality(Nullable(String))` | Код категории из источника |
| `brand` | `LowCardinality(Nullable(String))` | Бренд |
| `price` | `Decimal(12,2)` | Цена события |
| `user_id` | `UInt32` | Идентификатор пользователя |
| `user_session` | `Nullable(UUID)` | Идентификатор сессии |
| `event_date` | `Date` | Дата события |
| `_source_file` | `LowCardinality(String)` | Исходный файл |
| `_batch_date` | `Date` | Дата обрабатываемой партии |
| `_ingested_at` | `DateTime64(3, 'UTC')` | Время загрузки в ODS |

Технические поля `_source_file`, `_batch_date` и `_ingested_at` позволяют отслеживать происхождение данных и контекст загрузки.

Таблица использует `ReplacingMergeTree`, партиционирование по дате события (`toYYYYMMDD(event_date)`) и сортировку по `(user_id, event_time, product_id, event_type, event_id)` ориентированную на выборки пользовательской истории.

#### `fact_purchases`

Хранит события покупок для специализированной аналитики продаж. В таблице сохранены идентификаторы пользователя и товара, категория, бренд, цена, время события и технические поля происхождения данных.

Предназначена для выборок покупок и последующих расчётов показателей продаж. Фильтрация только по дате покупки позволяет эффективно ограничивать область чтения.

- Партиционирование по `event_date`
- Сортировка по `(event_date, event_id)`
- Движок `MergeTree`.

#### `fact_sessions`

Хранит агрегированные показатели пользовательских сессий.

| Поле | Тип ClickHouse | Описание |
|---|---|---|
| `session_id` | `String` | Идентификатор сессии |
| `user_id` | `UInt32` | Пользователь |
| `session_start` / `session_end` | `DateTime64(3, 'UTC')` | Начало и окончание сессии |
| `session_duration_seconds` | `Int64` | Длительность в секундах |
| `events_count` | `UInt64` | Количество событий |
| `views_count` | `UInt64` | Количество просмотров |
| `carts_count` | `UInt64` | Количество добавлений в корзину |
| `remove_from_cart_count` | `UInt64` | Количество удалений из корзины |
| `purchases_count` | `UInt64` | Количество покупок |
| `products_count` | `UInt64` | Количество товаров |
| `purchase_amount` | `Decimal(38,2)` | Сумма покупок |
| `session_date` | `Date` | Дата сессии |

- Партиционирование по месяцу `session_start`
- Сортировка по `(user_id, session_start, session_id)`.

Такая организация поддерживает анализ истории сессий пользователя и временных интервалов активности.

### 3.2. Измерения

#### `dim_user`

Содержит временные границы активности пользователя.

| Поле | Тип ClickHouse | Описание |
|---|---|---|
| `user_id` | `UInt32` | Идентификатор пользователя |
| `first_seen` | `DateTime64(3, 'UTC')` | Первое зафиксированное событие |
| `last_seen` | `DateTime64(3, 'UTC')` | Последнее зафиксированное событие |

- Движок `MergeTree`
- Сортировка по `user_id`.

#### `dim_product`

Измерение содержит основные классификационные атрибуты товара.

| Поле | Тип ClickHouse | Описание |
|---|---|---|
| `product_id` | `UInt32` | Идентификатор товара |
| `category_id` | `UInt64` | Идентификатор категории |
| `brand` | `Nullable(String)` | Бренд |

- Движок `MergeTree`
- Сортировка по `product_id`

#### `dim_category`

Содержит `category_path` – иерархию в виде массива строк, корневое и конечное названия.

| Поле | Тип ClickHouse | Описание |
|---|---|---|
| `category_id` | `UInt64` | Идентификатор категории |
| `category_code` | `Nullable(String)` | Код категории |
| `category_path` | `Array(String)` | Путь по иерархии категорий |
| `category_root_name` | `String` | Название корневой категории |
| `category_leaf_name` | `String` | Название конечной категории |

- Движок `MergeTree`
- Сортировка по `category_id`

## 4. Хранение и производительность

Таблицы используют движки семейства `MergeTree` с настройками партиционирования и сортировки, соответствующими их структуре и предполагаемым сценариям чтения.

- `fact_events` партиционируется по дням, что позволяет работать с отдельными датами событий.
- `fact_purchases` партиционируется по дате покупки.
- `fact_sessions` партиционируется по месяцу начала сессии.
- Измерения хранятся без временного партиционирования.

Ключи сортировки задают физический порядок данных в ClickHouse, но сами по себе не гарантируют уникальность ключей.

## 5. Связь со слоем витрин

Core предназначен для хранения и повторного использования фактов и измерений. На следующем этапе dbt формирует аналитические витрины в схеме `ecom_mcs_dwh_marts`.

Витрины включают показатели воронки, продаж, товаров, пользователей и сессий. Их структура и назначение описаны в [`marts.md`](marts.md).
