# Marts — аналитические витрины

## 1. Назначение

Слой  содержит аналитические витрины, формируемые с помощью dbt на основе данных Core.

Задачи слоя:
- подготовить данные для конкретных аналитических сценариев;
- предоставить согласованную структуру показателей для BI;
- отделить расчёты для отчётности от детализированного хранения событий.

Витрины потребляются в Apache Superset. Их определения и зависимости управляются в dbt.

## 2. Состав витрин

Схема `ecom_mcs_dwh_marts` включает:

| Витрина | Основное назначение | Ключевые показатели |
|---|---|---|
| `mart_funnel` | Анализ этапов пользовательской воронки | Количество событий на этапе, выручка |
| `mart_sales` | Аналитика продаж | Количество покупок, покупатели, проданные товары, выручка, средняя цена |
| `mart_products` | Анализ активности и продаж товаров | Просмотры, добавления и удаления из корзины, покупки, выручка |
| `mart_sessions` | Анализ пользовательских сессий | Длительность, события, просмотры, корзины, покупки, сумма покупок |
| `mart_users` | Анализ активности пользователей | События, просмотры, корзины, покупки, выручка, число сессий |

## 3. Структура витрин

### 3.1. `mart_funnel`

Предназначена для анализа воронки по дате, категории, бренду и этапу.

Основные поля:
- `event_date` — дата события;
- `category_id`, `category_root_name`, `category_leaf_name` — категория;
- `brand` — бренд;
- `funnel_stage` — этап воронки;
- `stage_count` — количество событий на этапе;
- `revenue` — выручка.

Группировка по этапам позволяет сравнивать активность на разных шагах пользовательского пути.

### 3.2. `mart_sales`

Предназначена для анализа продаж по дате покупки, категории и бренду.

Основные поля:
- `purchase_date` — дата покупки;
- `category_id`, `category_root_name`, `category_leaf_name` — категория;
- `brand` — бренд;
- `purchase_count` — количество покупок;
- `purchasing_users` — количество покупателей;
- `purchased_products` — количество купленных товаров;
- `revenue` — выручка;
- `avg_purchase_price` — средняя цена покупки.

### 3.3. `mart_products`

Предназначена для анализа активности и покупок в разрезе товаров и дат.

Основные поля:
- `event_date` — дата события;
- `product_id` — товар;
- `category_id`, `category_root_name`, `category_leaf_name` — категория;
- `brand` — бренд;
- `view_count` — просмотры;
- `cart_count` — добавления в корзину;
- `remove_from_cart_count` — удаления из корзины;
- `purchase_count` — покупки;
- `revenue` — выручка.

### 3.4. `mart_sessions`

Предназначена для анализа пользовательских сессий. 

- `session_id` - идентификатор;
- `user_id` — пользователь;
- `session_start` - время начала;
- `session_end` - время окончания;
- `session_duration_seconds` - длительность;
- `events_count` - количество событий;
- `views_count` - количество событий;
- `carts_count` - количество событий;
- `remove_from_cart_count` - количество событий;
- `purchases_count` - количество событий;
- `products_count` - число товаров;
- `purchase_amount` - сумму покупок;
- `session_date` - дата.

Структура показателей соответствует `fact_sessions` в Core и позволяет использовать сессионные характеристики в BI-отчётности.

### 3.5. `mart_users`

Предназначена для анализа активности пользователей по датам.

Основные поля:
- `event_date` — дата;
- `user_id` — пользователь;
- `event_count` — количество событий;
- `view_count` — просмотры;
- `cart_count` — добавления в корзину;
- `remove_from_cart_count` — удаления из корзины;
- `purchase_count` — покупки;
- `revenue` — выручка;
- `source_session_count` — количество сессий, учтённых моделью.

## 4. Хранение и производительность

Витрины используют `MergeTree`. Партиционирование выполняется по месяцу даты, кроме `mart_sessions`, которая также партиционируется по месяцу `session_start`.

| Витрина | Партиционирование | Ключ сортировки |
|---|---|---|
| `mart_funnel` | `toYYYYMM(event_date)` | `(event_date, category_id, brand, funnel_stage)` |
| `mart_sales` | `toYYYYMM(purchase_date)` | `(purchase_date, category_id, brand)` |
| `mart_products` | `toYYYYMM(event_date)` | `(event_date, product_id)` |
| `mart_sessions` | `toYYYYMM(session_start)` | `(session_start, user_id, session_id)` |
| `mart_users` | `toYYYYMM(event_date)` | `(event_date, user_id)` |

Данные настройки определяют физическую организацию данных в ClickHouse и помогают при запросах по соответствующим датам и ключам сортировки.

## 5. Связь с dbt и BI

dbt отвечает за преобразование данных Core в модели витрин и управление зависимостями между моделями. Apache Superset использует эти подготовленные витрины данные для построения аналитических представлений.

OpenMetadata и OpenLineage обеспечивают наблюдаемость происхождения данных вплоть до аналитических объектов. Подробности контроля качества и lineage описаны в соответствующих разделах документации.
