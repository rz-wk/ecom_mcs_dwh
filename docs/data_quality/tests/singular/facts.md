# Singular-тесты фактов

Файлы: `dbt/tests/<имя>.sql`.

## `fact_purchases_not_null` — Completeness

- **Проверка:** обязательные поля заполнены: `event_id`, `event_time`, `product_id`, `user_id`, `price`, `event_date`.
- **Провал:** модель потеряла обязательное значение при трансформации.
- **Действие:** проверить SQL модели и входные данные.

## `fact_purchases_positive_price` — Validity

- **Проверка:** `price >= 0`.
- **Провал:** нарушен инвариант цены, который уже контролируется при входе в Core.
- **Действие:** проверить модель `fact_purchases` и данные Core.

## `fact_purchases_unique` — Uniqueness

- **Проверка:** `event_id` уникален.
- **Провал:** возможен повторный incremental-прогон без корректной очистки.
- **Действие:** проверить инкрементальную логику и перезапустить модель за соответствующую дату.

## `fact_purchases_integrity` — Integrity

- **Проверка:** каждая запись `fact_purchases` существует в Core `fact_events` и соответствует событию `event_type = 'purchase'`; используется `LEFT JOIN`.
- **Провал:** модель включила событие другого типа или строку, которой нет в Core.

## `fact_sessions_validity` — Validity

- **Проверка:** `session_end >= session_start`, длительность неотрицательна, `events_count > 0`, все счётчики и `purchase_amount` неотрицательны.
- **Провал:** ошибка логики sessionization.
- **Действие:** проверить алгоритм реконструкции сессий и пересчитать `fact_sessions` за соответствующий период.

## `reconciliation_core_purchases` — Consistency

- **Проверка:** число событий `purchase` в `fact_events` по `_batch_date` равно числу записей в `fact_purchases` по `event_date`.
- **Провал:** модель потеряла или добавила покупки.
- **Действие:** проверить фильтрацию и инкрементальную логику `fact_purchases`, затем пересчитать затронутую дату.
- Переменная `batch_date` передаётся из DAG через `dbt_vars` в конфигурации Cosmos. Без неё тест пропускается; в штатном рабочем прогоне переменная должна быть задана.
- Результат отправляется в OM таском `push_dbt_test_results` на `fact_events`, поскольку коннектор не создаёт кейс для теста с зависимостями `source` и `ref`.

## `reconciliation_core_sessions` — Consistency

- **Проверка:** каждое событие batch покрыто ровно одной реконструированной сессией через `LEFT JOIN` по `user_id` и интервалу сессии. Учитываются события, начавшиеся до границы batch, если они входят в агрегаты соответствующих сессий.
- **Провал:** обнаружены непокрытые события или перекрытия сессий.
- **Действие:** проверить алгоритм sessionization и пересчитать `fact_sessions`.
- Результат отправляется в OM таском `push_dbt_test_results` на `fact_events`.
