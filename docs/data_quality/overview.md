# Назначение и принципы

Документ описывает систему контроля качества DWH: какие проверки существуют, где выполняются, как результаты попадают в OpenMetadata, как добавить новую проверку и что делать при сбоях. Принципы, стандарт покрытия и процедуры можно применять к другим хранилищам с аналогичной архитектурой.

## Задачи системы

Конвейер проходит путь:

`Source CSV -> PostgreSQL ODS -> PySpark -> ClickHouse Core -> dbt-модели -> BI-витрины`

На каждом этапе возможны ошибки:

- источник прислал некорректные строки или изменил контракт;
- загрузчик потерял либо задублировал строки;
- трансформация потеряла или некорректно дедуплицировала события;
- факты или агрегаты витрин разошлись с исходным слоем.

Система должна обнаруживать такие проблемы как можно ближе к месту возникновения — до распространения ошибки на последующие этапы. Результаты проверок передаются в OpenMetadata, где доступны состояние качества и история результатов.

## Основные принципы

1. **Одно свойство — один тест-владелец.** Перед добавлением проверки нужно свериться с [матрицей покрытия](tests/README.md). Объединённые диагностические проверки допустимы, но не должны размывать ответственность за отдельные свойства.
2. **Контроль на границе этапа.** Расхождение CSV и ODS останавливает конвейер до PySpark; проблема при переносе ODS в Core — до dbt.
3. **Механизм выбирается по области проверки.**
   - Несколько систем или журнал загрузки — Python-гейт.
   - Стандартное свойство колонки — dbt generic-тест.
   - Инвариант таблицы, грейн или бизнес-правило — dbt singular-тест.
   - Сверка разных слоёв DWH — singular-тест `*_reconciliation`.
4. **Имя теста кодирует его тип.** Dimension в OM назначается по имени теста согласно [naming.md](naming.md); для Python-гейтов dimension задаётся явно.
5. **Эталон берётся из данных, порог — из конфигурации.** Ожидаемые значения следует вычислять по журналу, контракту или второй стороне конвейера, а не фиксировать произвольными константами.
6. **OM — витрина, а не механизм блокировки.** Отправка результатов выполняется в режиме best-effort. Недоступность OM сама по себе не должна останавливать загрузку; блокировка определяется кодом проверки и кодом возврата таска.
7. **Матрица — источник истины по покрытию.** Если свойство не отражено в матрице, его покрытие не подтверждено документацией. Новые проверки необходимо вносить в матрицу вместе с их реализацией.

## Роли

- **DWH Engineer / BI Developer** — добавляет проверки по [standards.md](standards.md) и [procedures.md](procedures.md), обновляет матрицу и разбирает падения гейтов.
- **Analyst** — отслеживает состояние качества в OM и использует [матрицу тестов](tests/README.md) для интерпретации результатов.
