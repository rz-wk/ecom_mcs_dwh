# Словарь данных DWH `ecom_mcs_dwh`

## 1. Назначение

Документ описывает структуру аналитических таблиц, гранулярность данных и аналитический смысл полей в слоях Core и Marts. Описание моделей в [dbt-модели](../architecture/dbt.md).

> Поля, типы и дополнительные метрики следует сверять с актуальным DDL: при расширении dbt-модели раздел необходимо обновлять вместе с моделью и тестами.

## 2. Слои и таблицы

| Слой | Таблица | Гранулярность | Назначение |
|---|---|---|---|
| Core | `fact_events` | Одно событие | Очищенный поток событий |
| Core | `dim_user` | Один пользователь | Первая и последняя активность |
| Core | `dim_product` | Один товар | Последние известные атрибуты товара |
| Core | `dim_category` | Одна категория | Путь категории, корневой и конечный уровни |
| Core | `fact_purchases` | Одно событие покупки | Представление покупок |
| Core | `fact_sessions` | Одна восстановленная сессия | Событийная активность пользователя в рамках сессии |
| Marts | `mart_funnel` | День x категория x бренд x этап | События пользовательского пути |
| Marts | `mart_sales` | Дата покупки x категория x бренд | Продажи, покупатели и выручка |
| Marts | `mart_products` | День x товар | Дневные показатели товара |
| Marts | `mart_sessions` | Одна сессия | Метрики восстановленных сессий |
| Marts | `mart_users` | День x пользователь | Дневная активность пользователя |

Гранулярность — основной контракт каждой таблицы.

## 3. Core

### 3.1. `fact_events`

- **Назначение:** основной очищенный набор событий, используемый как источник измерений, фактов и витрин
- **Гранулярность:** одна строка на одно очищенное событие.

| Поле | Тип | Смысл | Примечание |
|---|---|---|---|
| `event_id` | `UInt64` | Идентификатор события в Core | Используется для уникальности и детерминированной сортировки |
| `event_time` | `DateTime64(3, 'UTC')` | Время события | Временная ось пользовательского поведения |
| `event_date` | `Date` | Дата события | Используется для инкрементальной обработки и партиционирования downstream-моделей |
| `event_type` | `LowCardinality(String)` | Тип события | Например, `view`, `cart`, `remove_from_cart`, `purchase` |
| `product_id` | `UInt32` | Идентификатор товара | Может участвовать в группировках и соединениях с `dim_product` |
| `category_id` | `UInt64` | Идентификатор категории | Используется для сегментации |
| `category_code` | `LowCardinality(Nullable(String))` | Иерархический код категории | Может быть пустым; используется для построения `dim_category` |
| `brand` | `LowCardinality(Nullable(String))` | Бренд товара | Может быть пустым |
| `price` | `Decimal(12, 2)` | Цена события | Не следует трактовать как постоянную цену товара |
| `user_id` | `UInt32` | Идентификатор пользователя | Используется для пользовательских измерений и сессий |
| `user_session` | `Nullable(UUID)` | Идентификатор сессии из источника | Сохраняется как атрибут события; не определяет границы `fact_sessions` |

### 3.2. `fact_purchases`

- **Назначение:** события покупки, выделенные из `fact_events`
- **Гранулярность:** одна строка на событие с `event_type = 'purchase'`.

| Поле | Тип | Смысл |
|---|---|---|
| `event_id` | `UInt64` | Идентификатор события покупки |
| `event_time` | `DateTime64(3, 'UTC')` | Время покупки |
| `event_date` | `Date` | Дата покупки для фильтрации и партиционирования |
| `user_id` | `UInt32` | Покупатель |
| `product_id` | `UInt32` | Купленный товар |
| `category_id` | `UInt64` | Категория товара на момент события |
| `brand` | `LowCardinality(Nullable(String))` | Бренд на момент события |
| `price` | `Decimal(12, 2)` | Цена события покупки |
| `user_session` | `Nullable(UUID)` | Идентификатор сессии из источника |

Таблица сохраняет событийную гранулярность. Отдельного идентификатора заказа в описанной модели нет.

### 3.3. `fact_sessions`

- **Назначение:** сессии, восстановленные по временной последовательности событий
- **Гранулярность:** одна строка на восстановленную сессию.

| Поле | Тип | Смысл |
|---|---|---|
| `session_id` | `String` | Детерминированный идентификатор восстановленной сессии |
| `user_id` | `UInt32` | Пользователь |
| `session_start` | `DateTime64(3, 'UTC')` | Время первого события сессии |
| `session_end` | `DateTime64(3, 'UTC')` | Время последнего события сессии |
| `session_date` | `Date` | Дата начала сессии |
| `events_count` | `UInt64` | Количество событий в сессии |
| `session_duration_seconds` | `Int64` | Длительность сессии в секундах |

Границы сессии определяются по разрыву между событиями одного пользователя: разрыв строго больше 30 минут начинает новую сессию. Сессии не выводятся напрямую из `user_session`.

Идентификатор вычисляется из `user_id` и `session_start`. При изменении начала сессии меняется и `session_id`.


### 3.4. `dim_user`

- **Назначение:** временные границы активности пользователя
- **Гранулярность:** одна строка на `user_id`.

| Поле | Тип | Смысл |
|---|---|---|
| `user_id` | `UInt32` | Идентификатор пользователя |
| `first_seen` | `DateTime64(3, 'UTC')` | Время первого известного события пользователя |
| `last_seen` | `DateTime64(3, 'UTC')` | Время последнего известного события пользователя |

`first_seen` и `last_seen` рассчитываются по полной доступной истории пользователя.

### 3.5. `dim_product`

- **Назначение:** последние известные атрибуты товара
- **Гранулярность:** одна строка на `product_id`.

| Поле | Тип | Смысл | Примечание |
|---|---|---|---|
| `product_id` | `UInt32` | Идентификатор товара | Ключ измерения |
| `category_id` | `UInt64` | Последняя известная непустая категория товара | Определяется по событиям |
| `brand` | `Nullable(String)` | Последний известный непустой бренд | Определяется по событиям |

Цена не хранится как постоянный атрибут в этом измерении: `price` относится к событию и может меняться.

### 3.6. `dim_category`

- **Назначение:** аналитическое представление категорий, построенное по `category_code`
- **Гранулярность:** одна строка на `category_id`.

| Поле | Тип | Смысл |
|---|---|---|
| `category_id` | `UInt64` | Идентификатор категории |
| `category_code` | `Nullable(String)` | Последний известный непустой код категории |
| `category_path` | `Array(String)` | Полный путь категории, представленный массивом компонентов |
| `category_root` | `String` | Первый компонент пути категории |
| `category_leaf` | `String` | Последний компонент пути категории |

Путь формируется разбиением `category_code` по точке. Это производное представление, а не полноценная иерархия с отдельными ключами родительских категорий.

Если в событиях отсутствует `category_code`, достоверный путь категории из этого источника восстановить нельзя.

## 4. Marts

### 4.1. `mart_funnel`

- **Назначение:** агрегаты событий по этапам пользовательского пути
- **Гранулярность:** `event_date x category_id x brand x stage`.

| Поле | Тип | Смысл |
|---|---|---|
| `event_date` | `Date` | Дата событий |
| `category_id` | `UInt64` | Категория товара |
| `brand` | `LowCardinality(String)` | Бренд товара |
| `stage` | `LowCardinality(String)` | Этап пути: `view`, `cart`, `remove_from_cart` или `purchase` |
| `stage_count` | `UInt64` | Число событий соответствующего этапа |
| `revenue` | `Decimal(38, 2)` | Сумма цены для событий покупки в группе |

`category_id = 0` и пустой `brand` используются в качестве замены отсутствующих значений для группировки. Эти значения не являются идентификаторами реальной категории или бренда.

`stage_count` — количество событий, а не количество уникальных пользователей, сессий или товаров. Сумма по этапам не должна автоматически интерпретироваться как число уникальных пользователей в воронке.

### 4.2. `mart_sales`

- **Назначение:** агрегаты продаж по дате, категории и бренду
- **Гранулярность:** `purchase_date x category_id x brand`.

| Поле | Тип | Смысл |
|---|---|---|
| `purchase_date` | `Date` | Дата покупки |
| `category_id` | `UInt64` | Категория товара |
| `brand` | `LowCardinality(String)` | Бренд товара |
| `purchase_count` | `UInt64` | Количество событий покупки |
| `purchasing_users` | `UInt64` | Число уникальных покупателей |
| `purchased_products` | `UInt64` | Число уникальных товаров |
| `revenue` | `Decimal(38, 2)` | Сумма цены событий покупки |
| `avg_purchase_price` | `Float64` | Средняя цена события покупки |

`purchase_count` считает события, а не заказы. `purchasing_users` и `purchased_products` рассчитываются как точное число уникальных значений в соответствующей группе.

Показатели следует интерпретировать в рамках событийной модели источника: она не содержит отдельной сущности заказа, позволяющей без дополнительных правил агрегировать события в заказы.

### 4.3. `mart_products`

- **Назначение:** дневные показатели активности и покупок по товарам
- **Гранулярность:** `event_date x product_id`.

| Поле | Тип | Смысл |
|---|---|---|
| `event_date` | `Date` | Дата событий |
| `product_id` | `UInt32` | Идентификатор товара |
| `category_id` | `UInt64` | Категория товара из измерения |
| `brand` | `Nullable(String)` | Бренд товара из измерения |
| `view_count` | `UInt64` | Количество событий просмотра |
| `cart_count` | `UInt64` | Количество событий добавления в корзину |
| `remove_from_cart_count` | `UInt64` | Количество событий удаления из корзины |
| `purchase_count` | `UInt64` | Количество событий покупки |
| `revenue` | `Decimal(38, 2)` | Сумма цены событий покупки |

Атрибуты товара присоединяются из измерений. Поэтому категория и бренд отражают последние известные атрибуты товара, а не обязательно значение, действовавшее в дату исторического события.

### 4.4. `mart_sessions`

- **Назначение:** аналитическое представление восстановленных пользовательских сессий
- **Гранулярность:** одна строка на `session_id`.

| Поле | Тип | Смысл |
|---|---|---|
| `session_id` | `String` | Идентификатор восстановленной сессии |
| `user_id` | `UInt32` | Пользователь |
| `session_start` | `DateTime64(3, 'UTC')` | Начало сессии |
| `session_end` | `DateTime64(3, 'UTC')` | Окончание сессии |
| `session_date` | `Date` | Дата сессии |
| `events_count` | `UInt64` | Число событий сессии |
| `session_duration_seconds` | `Int64` | Длительность сессии в секундах |

Витрина использует сессии, рассчитанные в `fact_sessions`. Правила определения сессий описаны в разделе `fact_sessions`.


### 4.5. `mart_users`

- **Назначение:** дневная активность пользователей и связанные с ней показатели
- **Гранулярность:** `event_date x user_id`.

| Поле | Тип | Смысл |
|---|---|---|
| `event_date` | `Date` | Дата активности |
| `user_id` | `UInt32` | Пользователь |
| `event_count` | `UInt64` | Общее количество событий пользователя за день |
| `view_count` | `UInt64` | Количество событий просмотра |
| `cart_count` | `UInt64` | Количество событий добавления в корзину |
| `remove_from_cart_count` | `UInt64` | Количество событий удаления из корзины |
| `purchase_count` | `UInt64` | Количество событий покупки |
| `revenue` | `Decimal(38, 2)` | Сумма цены событий покупки |
| `source_session_count` | `UInt64` | Число уникальных значений исходного `user_session` за день |

`source_session_count` рассчитывается по исходному идентификатору сессии из событий. Он не равен автоматически числу сессий в `fact_sessions`, поскольку `fact_sessions` использует собственный алгоритм сегментации по временным разрывам.

## 5. Интерпретация метрик

| Метрика | Единица подсчёта | Важное ограничение |
|---|---|---|
| `stage_count` | События этапа | Не уникальные пользователи |
| `purchase_count` | События покупки | Не заказы |
| `purchasing_users` | Уникальные пользователи в группе | Один пользователь учитывается один раз внутри группы |
| `purchased_products` | Уникальные `product_id` в группе | Не количество проданных единиц |
| `revenue` | Сумма `price` событий покупки | Зависит от полноты и семантики `price` |
| `avg_purchase_price` | Средняя цена события покупки | Не средний чек заказа |
| `events_count` | События восстановленной сессии | Определяется алгоритмом сессий |
| `source_session_count` | Уникальные исходные `user_session` | Не число восстановленных сессий |

## 6. Контроль качества

Проверки уникальности, обязательности полей, допустимых значений и сверок между слоями поддерживаются системой контроля качества.

- Описание generic- и singular-тестов: [контроль качества данных](../data_quality/README.md).
- Сводная матрица тестов: [data_quality/tests/](../data_quality/tests/README.md).


## 7. Ограничения модели данных

1. Источник событий не содержит отдельного ключа заказа, поэтому показатели покупок в текущем виде основаны на событиях `purchase`.
2. `dim_product` и `dim_category` представляют последние известные атрибуты, а не исторические версии измерений.
3. `fact_sessions` использует собственное правило определения сессии, не исходный `user_session`.
